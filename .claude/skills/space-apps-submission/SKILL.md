# NASA Space Apps 2026 submission

Project: **AstroVital**. Demo flow lives in `docs/DEMO_SCRIPT.md` (Turkish, team-internal); everything shown to judges is English.

Challenge: **Create Health Monitoring Software for Astronauts on Space Missions**
https://www.spaceappschallenge.org/2026/challenges/health-monitoring-software/

## Hard rules (Project Submission Guide)

- Everything judges see is **in English** (project page, README, slides). A video may be spoken in another language but must have **English subtitles**.
- Demo is **either a video of max 30 seconds or a slide deck of max 7 slides including the title slide**. Exceeding the limit = not eligible for global judging.
- Demo is hosted externally (YouTube, Drive, GitHub…) with a **public** link.
- Show clearly **which space-agency data/resources were used and how** (NASA HRP hazards & risks, NASA-STD-3001, CSA Bio-Monitor, NOAA/NASA space weather, etc.).
- Code in a public repository.
- Source: https://www.spaceappschallenge.org/resources/project-submission-guide/

## Judging criteria — map every claim to one

Impact · Creativity · Validity · Relevance · Presentation
(https://www.spaceappschallenge.org/resources/judging-awards-guide)

## 7-slide skeleton

1. Title — team name, members, challenge name
2. Problem — 5 hazards → crew must self-assess, Earth help is far away
3. Solution — one screenshot, one sentence
4. How it works — measure → compare to baseline/threshold → explain → act → escalate
5. Space-agency data & sources used
6. Demo highlights / what's real vs simulated
7. Impact & next steps

## 30-second video skeleton

0–3 s team + challenge · 3–8 s problem · 8–25 s app walkthrough (one alert end-to-end) · 25–30 s data used + impact.

## Final checklist

- [ ] Limits respected (≤30 s or ≤7 slides)
- [ ] English everywhere / subtitles
- [ ] Public links tested in a private window
- [ ] "Prototype, simulated data, not a medical device" stated
- [ ] README has run instructions and data sources
